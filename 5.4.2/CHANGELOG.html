    Changelog¶

    All notable changes to Open-ALAQS are listed here. Format follows Keep a Changelog loosely; dates are ISO 8601.

    [5.4.2] - 2026-11-02¶

    Upgrading a 5.4.1 study: see Upgrading from 5.4.1. Results of the shipped examples and of the validation fixtures do not change (plugin, standalone and CAEP14 reference outputs identical to 5.4.1). The fixes below change results only for the cases they name.

    Fixed¶

    • Calculate Dispersion, Generate from OpenALAQS output: the emission settings (Method, Apply NOx Corrections, Atmosphere Aloft, BFFM2 Fuel-Flow Source, Source Dynamics) can be set as on the Configuration tab of Visualize Emission Calculation. The emissions were always recalculated with bymode, no NOx correction and no source dynamics, which stay the defaults. With BFFM2, all ticked pollutants are calculated as in any BFFM2 run, so CO2, SOx and PM10 change too (BFFM2 fuel flow).
    • Calculate Dispersion: Roughness Length, Displacement Height and Anemometer Height can be set in both Generate options; they were always 0.1 / 0.6 / 10.6 m. The defaults (0.1 m, 0, 0; 0 derives the value from z0) write the same austal.txt as before.
    • Calculate Dispersion, Generate from OpenALAQS output: flight segments and roadways are clipped to the calculation grid, as in the Dispersion Models tab; the emissions of segments beyond the grid were counted in the AUSTAL source rates. Results change for studies whose flight paths or roadways extend beyond the grid (for example NOx 1.775 to 1.770 g/s in one hour of the AIRPORT_A test study).
    • Calculate Dispersion: the receptor height (Receptors CSV column height, or the height stored with the inventory's receptor points) is passed to AUSTAL; every receptor was placed at 1.5 m. The receptor points stored in a study are now written to austal.txt; reading them failed for every study, so none were written.
    • Calculate Dispersion, Generate from CSV: a PM10 fine fraction field (default 0.9, as before).
    • Calculate Dispersion: with NOTALUFT ticked, the options string keeps SCINOTAT (NOSTANDARD;NOTALUFT;SCINOTAT;Kmax=1), as the standalone writes it. Output files of NOTALUFT runs are written in scientific notation (format only); the result windows read both notations.
    • Taxi: with only set_time_of_main_engine_start_before_takeoff_in_s set, single-engine taxi was applied to the end of the taxi, after the main engines start; it now applies before that point. Results change for movements that set this field (no shipped example does).
    • Taxi: with single-engine taxi set and no taxi segment inside the single-engine window, the start emissions of the single-engine-taxi engines were not counted; every engine now starts once per departure.
    • Taxi: with gate_emissions_code 0, the start emissions of the single-engine-taxi engines were still added; they are now left out, like the other start, GSE and GPU emissions.
    • Taxi: the queue of a departure with single-engine taxi was counted on the engine count of the last route segment, even when the main engines start during the queue. It is now split at the main engine start: before it on taxi_engine_count engines with taxi_fuel_ratio, as a single-engine segment, after it on all engines. Results change for departures with taxi_engine_count, a main engine start time and a queue (no shipped example sets these times).
    • Standalone (and the Dataiku library): single-engine taxi as in the plugin. The standalone ran all taxi on all engines and multiplied the whole route by taxi_fuel_ratio. It now reads taxi_engine_count and the three main engine start/off times, runs the route segments and the part of a departure's queue on the single-engine side of those times on taxi_engine_count engines with taxi_fuel_ratio, and everything else on all engines without the ratio; the taxi emission is placed on the route segments accordingly. taxi_fuel_ratio without a main engine time no longer has an effect, as in the plugin. Results change for movements with a main engine start/off time or a taxi_fuel_ratio other than 1 (none in the shipped examples); with them, plugin and standalone movement totals now agree to 1e-8 or better (they differed by up to 68 %).
    • Taxi with BFFM2: an engine without an emission index at the taxi thrust stopped the calculation with an error; the movement now gets no taxi emissions and the log names the missing index.
    • Engine tests with the BFFM2 thrust mode: the meteo row is the one nearest to the event midpoint; the plugin always used the last row of the meteo table. Results change for BFFM2 engine tests when the meteo table has more than one row. The standalone looks up the exact midpoint too; it rounded it down to the second, which picked the other row at a tie.
    • Movements file with a missing, misspelt or unknown header name: rows with 20 fields are read in the documented column order (with gate_emissions_code after apu_code) instead of being shifted from column 13 on, and the log names the unknown and missing headers. A header that ends with domestic (old files) keeps the old order: the 19 legacy columns, then gate_emissions_code when present. Files with a correct header are read as before.
    • Movements file without a header line: the first line was taken as the header, so the first movement was lost; the file check also left it out of the movement count and the study period. A first line that starts with a date is now read and checked as a movement, by position, with a warning.
    • Calculation settings: choosing a pollutant no longer resets Method from BFFM2 to bymode; after a pollutant without BFFM2, selecting CO, HC or NOx brings BFFM2 back. Loading a configuration replaces that remembered choice.
    • Standalone and CAEP14 reference: the meteo row of a movement is the one nearest to the start of its hourly period, and the LTO ceiling is 914.4 m when the row has no mixing height. This matches the plugin for a study with hourly periods: the standalone and the reference always use hourly periods starting on the hour, while the plugin uses the study's time interval. They took the latest row at or before the runway time and fell back to the study's vertical limit. Results change only with missing or off-hour meteo rows, movements before the first meteo row, or an empty mixing height with a study vertical limit other than 914.4 m.
    • Standalone: BFFM2 segments that fall back (ADS-B fuel flow above the plausibility ceiling, or no power and no fuel flow) are reported with one warning per movement, as in the plugin.
    • python -m austal_prep reads source_aggregation, source_offset_cells and max_receptors from config.json; the defaults always applied.
    • Gate emissions: the log warning for an aircraft group matched to a near gate profile group named the two groups the wrong way round.
    • Movements calculated together: the flight emissions are calculated once per group of movements with the same engine, profile, runway and taxi route, the taxi emissions once per group with the same engine, route and taxi settings, and the gate emissions once per gate, aircraft group and direction. Each group used the aircraft, the tow_ratio or the gate_emissions_code of its first movement. The aircraft type and tow_ratio are now part of the flight key, the aircraft type of the taxi key and gate_emissions_code of the gate key. Results change for a movement whose aircraft type shares an engine and a profile with another type of a different engine count in the same hour (in the default data 86 engine and profile pairs are shared by types with different engine counts, for example A4 with one engine and A6 with two on 07P05GE220 and JET-MEDIUM-D-1), for movements with different tow_ratio with the NOx correction, and for movements with different gate_emissions_code at one gate.
    • Movements calculated together, tracks: the flight key did not hold the movement's track (track_id, shapes_tracks) or its runway direction, both of which shape the trajectory at the runway, so a movement flown along a track took the trajectory of a group member without one (or the reverse). Both are now part of the key. Results change for studies with tracks: on the training study, an A20N departure along a turning track next to one without got 4.18 kg NOx (bymode) instead of its own 4.32 kg. The standalone does not follow tracks (see its README, Limitations).
    • BFFM2: a profile point with no power setting and a zero or negative fuel flow stopped the whole calculation (TypeError); the segment now takes the bymode index, as a point with neither value.
    • BFFM2 taxi: an engine_thrust_level_for_taxiing outside the range of the twin-quadratic fit (for example 7 given for 7 %) stopped the whole calculation; the taxi now takes the TX mode values, with an error in the log.
    • NOx correction: a tow_ratio of 0, a negative value or NaN is replaced by 1 with a warning, in the plugin and the standalone; 0 made the plugin's correction factor negative (NOx −2.36 kg for a departure of the training study). The standalone already used 1 for 0 and negative values, without a warning, and gave NaN NOx for NaN.
    • Standalone and CAEP14 reference aligned with the plugin on edge cases that the shipped fixtures do not reach: BFFM2 taxi at the movement's engine_thrust_level_for_taxiing (they used the idle fuel flow for any thrust), with the plugin's fallback for a thrust outside the fit; a flight segment with a power setting above 1.05 or below 0 and no supplied fuel flow takes the bymode index (the standalone kept the BFFM2 index, the reference extrapolated the fit and had no 1.0 to 1.05 clamp); a supplied fuel flow of 0 or below counts as none; a NaN tow_ratio counts as 1 in the standalone NOx correction.
    • BFFM2: the log message for a power setting outside the twin-quadratic range said "falling back to mode-anchor EI"; the segment takes the bymode index, and the message now says so. The fit's own error said "between 0.07 and 1.0", though 0 to 0.07 is accepted (extrapolated from the idle point); it now says "between 0 and 1.0".
    • Taxiway Routes Editor: the log warning "No routes defined" was written whenever the route list was refreshed without selecting a route, also when the study has routes; it is now written only when the study has none.

    Changed¶

    • Reference data, default_airports (airport list of the ICAO lookup in the study setup): 5,035 airports instead of 5,060. 25 airports removed; 6 change their ICAO code, with the same name and position (SLCH to SLHI, SVAJ to SVNJ, VAHB to VOHB, WAJW to WAVV, WAMP to WAFP, WRKO to WATO); 55 elevations updated. Other rows unchanged. The table is not used by the emission calculation; new studies get it from the project template, and an existing study gets it with scripts/migrate_alaqs.py --refresh-reference-data (the table is in the default refresh set).
    • Study setup and calculation settings: the Vertical Limit fields are greyed out with a tooltip: they have no effect (the LTO ceiling is the hourly mixing height, or 914.4 m).
    • Gate emissions: aircraft of the group PROPELLER get no GSE or GPU emissions by design; this is now explicit in the code and the documentation (no change in results).
    • Documentation reorganised by reader (documents/user, methods, validation, developer), one page per topic, with an index, a glossary, input formats, troubleshooting, and a searchable site (tools/docs_site/mkdocs.yml); statements that disagreed with the code are corrected. tools/check_doc_links.py and .github/workflows/docs.yaml check the links on each pull request.
    • Documentation site published on GitHub Pages (https://eurocontrol-asu.github.io/open_alaqs/), one version per release (/<version>/, and /latest/ for the newest), built by .github/workflows/docs.yaml on each v* tag or when started by hand.
    • Toolbar: new Open ALAQS documentation button, and the About dialog links to the documentation; both open the site version of the installed plugin (/latest/ for a development version). The homepage in metadata.txt stays the EUROCONTROL page.
    • Dialog and form screenshots of the documentation retaken from the current forms with tools/docs_site/make_screenshots.py.
    • Aircraft emissions: a worked example runs one approach segment through bymode and the two BFFM2 fuel-flow sources, step by step (documents/methods/AIRCRAFT_EMISSIONS.md).
    • Training course slides (March 2026): an errata page lists where they differ from 5.4.1 (documents/user/TRAINING_COURSE_ERRATA.md).
    • Aircraft emissions documentation: where OpenALAQS differs from the published SAE methods, and by how much: the CO and HC curve between approach and climb-out (CAEP/14 rule, not SAE AIR 5715), no extrapolation below idle, the unscaled mode_anchor fuel flow (SAE AIR6183), the static conditions of the delta sqrt(theta) fuel scaling, the single NOx P3T3 exponent, and the taxi fuel flow (SAE AIR8035). The references to a "Doc 9889 Appendix 2" fuel-flow correction are replaced by SAE AIR 5715 (no change in results).
    • External links updated (ICAO Doc 9889, FOCA engine emissions, COPERT, QGIS installer).

    Removed¶

    • scripts/update-strings.sh and scripts/compile-strings.sh: translation helpers for an i18n/ folder removed in 2021; the plugin has no translations.
    • scripts/run-env-linux.sh: QGIS 2 environment helper.
    • documents/developer/design/FUEL_FLOW_OPTIONS.md: design note based on non-public study material. What is implemented (the δ √θ fuel-flow scaling) is described in documents/methods/AIRCRAFT_EMISSIONS.md; the options not implemented are no longer documented.

    Tests¶

    • Regression tests for each fix above, and test_emission_calculation passes on QGIS 3.34 (the minimum version), where QGIS's own unordered layer comparison mis-pairs the fields.

    [5.4.1] - 2026-10-24¶

    Upgrading a 5.4.0 study: see Upgrading from 5.4.0 in the User Guide. Every BFFM2 inventory changes and should be recalculated; bymode inventories change only in the PM10 of segments above 3,000 ft (MEEM V1). No option gives 5.4.0 BFFM2 results back: ground_held restores the 5.4.0 ambient conditions only, the fuel-flow fix has no switch.

    BFFM2 trajectory fuel flow and ambient conditions aloft. Results change for the BFFM2 methods. The fuel-flow fix (Fixed) changes bffm2_traj with ANP profiles (the fuel flow from the thrust share), the BFFM2 taxi fuel flow (bffm2_traj and bffm2_anchor) and BFFM2 engine tests in every study whose meteo is not ISA, and bffm2_traj in flight also at ISA (the e^(-0.2 M^2) term goes: +3 % at Mach 0.4). The atmosphere aloft (Changed) changes the BFFM2 indices of flight segments, the bffm2_traj fuel flow, the BFFM2 taxi and engine tests (station pressure) and, for every method including bymode, the MEEM V1 nvPM of segments above 3,000 ft (local T and p). bymode fuel, NOx, CO and HC are unchanged. Combined, on the example inventory (example/training, 13 movements): bffm2_traj NOx -11.3 %, CO2 -5.3 %, CO -1.7 %; bffm2_anchor NOx +0.3 %, CO -2.9 %, HC -4.9 %; bymode PM10 -0.01 %. Warm or windy studies should expect BFFM2 NOx changes above 10 %.

    Fixed¶

    • scripts/migrate_alaqs.py: a 5.3.x study that had been edited in QGIS kept integer or text fields after the migration. QGIS writes per-column layer statistics (geometry_columns_field_infos) each time a layer is edited and, when they exist, types the fields from them rather than from the declared column types; the script rebuilt the shapes_* tables with REAL columns but left those rows, so the forms still refused a decimal with "Upgrade the study with scripts/migrate_alaqs.py" and the study still logged the unmigrated warning when opened. The rows of a rebuilt table are now removed, and a study retyped by the 5.4.0 script gets a ~ STATISTICS plan step that removes them (run the script again). QGIS then types REAL as Double on 3.34 and 3.44 and recomputes the statistics on its next edit; the layer's extent and row count are kept (tests/test_migrate_layer_statistics.py). The bundled example and test studies carry no such rows, which is why the 5.4.0 tests did not see it.
    • The fuel flow read on the ICAO curve at the thrust share is scaled to ambient with delta * sqrt(theta), the corrected-parameter scaling of gas-turbine performance (the corrected fuel flow, fuel flow / (delta sqrt(theta)), a function of the corrected thrust, thrust / delta, and Mach), in the plugin (Engine.getEmissionIndexByEngineState) and the standalone (compute_aircraft, taxi, compute_engine_test). It was delta / theta^3.8 / exp(0.2 M^2), the inverse of the BFFM2 conversion of a known fuel flow to reference conditions (SAE AIR5715), which is an emission-index step, not a fuel-flow model: the fuel flow fell with rising temperature (-12 % at 25 C, where the scaling gives +1.7 %). The emission indices are the standard BFFM2 lookup at the new ambient fuel flow, as for a supplied (ADS-B / CUSTOM) fuel flow. Training fixture (280.5-295 K, 99 400 Pa), fix alone: bffm2_traj CO2 -2.5 %, NOx -6.6 %; bffm2_anchor (taxi) CO2 -0.7 %, NOx -0.3 %, CO -2.9 %, HC -4.1 %. The CAEP/14 BFFM2 reference cases (index step) are unchanged; the CAEP14 reference implementation, the pinned plugin outputs and the training validation workbooks are updated. In the standalone austal pipeline (and the Dataiku recipe) engine tests are computed with the ICAO mode values ("snap") as in 5.4.0, so neither this fix nor the atmosphere option reaches them there; it applies to engine tests in the plugin and to direct calls of compute_engine_test_for_period with a database connection.

    Changed¶

    • AUSTAL site parameters: one default for the plugin's AUSTAL output module, the standalone (aircraft and austal subcommands), austal_prep and the Dataiku recipe (open_alaqs/core/tools/surface_layer_atmosphere.site_parameters): z0 0.1 m, the TA Luft (2021, Anhang 2) roughness length of airports; d0 6 z0 (0.6 m); ha 10 m + d0 (10.6 m), AUSTAL's own defaults. d0 and ha are derived from z0 whenever they are left empty (None, "", null; 0 in the plugin's spin boxes, which cannot be empty), so changing z0 alone keeps the three consistent. They were 0.2 / 1.2 / 11.2 m in the plugin (three independent fields) and 0.3 m / 4 z0 / 11.2 m in the standalone austal pipeline and austal_prep. Results change for the AUSTAL concentrations of studies that keep the defaults (dilution: AUSTAL derives its wind and turbulence profiles from z0, d0, ha and the hourly wind); studies with explicit values are unchanged. Emissions change only with the surface_layer atmosphere (not the default): on training_v3, bffm2_traj NOx -0.015 % against the old plugin defaults and -0.024 % against the old standalone defaults (CO2 -0.004 % / -0.007 %). How to choose the three values from the land cover (CORINE, TA Luft classes) and the anemometer site: user guide, "Roughness length, displacement height and anemometer height". The METAR converter still assigns the Obukhov length independently of z0 (a known limitation; a separate, later change).
    • Ambient conditions aloft (atmosphere_model; documents/ATMOSPHERE_ALOFT.md, open_alaqs/core/tools/surface_layer_atmosphere.py). The temperature, pressure and humidity of each flight segment are those at its start height, carried up from the hourly meteo row; until 5.4.0 the row was used at every height, with its sea-level pressure (QNH) as the ambient pressure.
    • standard_lapse (default): the station pressure from QNH and the airport elevation and the 2 m temperature, carried up with the ISA lapse rate and the hydrostatic law; humidity ratio of the ground air kept.
    • surface_layer (option): the boundary-layer temperature profile of AUSTAL 3.3 (BlmTemp, TalBlm.c) from the hour's wind, Obukhov length and mixing height, T* from the hour's temperature, without AUSTAL's -30/+40 C limits, the stability term up to the mixing height (stable hours: at most AUSTAL's stable mixing height, getHm; a missing, NaN or non-positive mixing height keeps that cap), -8.5 K/km above. The surface sensible heat flux implied by the row's wind and Obukhov length is bounded at 600 W/m2 (unstable) and 100 W/m2 (stable), OpenALAQS engineering limits: above them L is replaced by the value that gives the bounded flux, with a warning (the AUSTAL time series keeps the row's L for those hours).
    • ground_held: the hourly row at every height, the 5.4.0 ambient conditions (the fuel-flow fix still applies).
    • Checked against the De Bilt radiosondes of 2025 (450 soundings; the hourly METAR-derived rows of an airport about 50 km away as input; within the emission ceiling): T(z) - T(surface) bias / RMS for standard_lapse -1.3 / 2.9 K at 100 m, +0.3 / 1.4 K at 300 m, +2.0 / 3.1 K at 900 m; surface_layer -1.5 / 2.8, -1.2 / 1.7, -2.7 / 3.5 K (too cold, not more accurate). The fuel-flow factor delta sqrt(theta) at height is within 0.3 to 0.7 % RMS of the soundings for both, against 1.2 % (100 m) to 12.9 % (900 m) for the ground row held. standard_lapse is therefore the default (an earlier candidate had surface_layer). In summer the AUSTAL profile is the closer one above 300 m (July and August, 600 m: 1.5 K RMS against 3.0 K, on 15 soundings); see documents/ATMOSPHERE_ALOFT.md, section 6.
    • Applies to the Mach number, the bffm2_traj fuel flow, the BFFM2 indices and the MEEM V1 non-LTO ambient (all methods, bymode included; MEEM V1 then uses the local T and p instead of the method's ISA + delta T, and the delta T is not used) of flight segments; the BFFM2 taxi and BFFM2 engine tests use the station pressure. The ICCAIA NOx correction keeps the hourly row. ISA meteo (standalone --isa-meteo, or a period without a tbl_InvMeteo row) stays ISA at every height.

    Changed¶

    AUSTAL grid_writer_mode default flipped to hybrid¶

    The default grid_writer_mode is now "hybrid" (was "time_indexed"). In hybrid mode, aircraft sub-sources receive one per-hour e-file per hour with per-pollutant spatial weights; stationary sources keep a single time-invariant e-file. The previous default (time_indexed) collapsed all aircraft activity over the study window into one shared spatial distribution, biasing per-pollutant dispersion: a cross-check on a 144-hour campaign run found correlation 0.823 against the QGIS plugin's AUSTAL output and a 6.1% deficit in total in-grid annual mean concentration. The bias was attributable entirely to the time-invariant spatial pattern (Monte Carlo at qs=3 vs qs=4 contributed correlation 0.9999, well inside noise).

    Changes: - austal_prep/config.py: grid_writer_mode field default flipped. Docstring rewritten to describe all three modes accurately. - openalaqs_standalone/orchestrate.py: function default flipped; new --grid-writer-mode {legacy,time_indexed,hybrid} CLI flag with default hybrid. - openalaqs_standalone/make_config.py: function default and docstring flipped.

    The hybrid writer code path itself (write_grid_per_hour_aircraft in austal_prep/writers/grid_files.py, plus the per-pollutant expansion logic in austal_prep/runner.py) was already present in 5.1.2 but exercised only via explicit opt-in. This release flips the default so it ships activated.

The per-source e000N.dmna files were written with a uniform 50 m first cell (sk from Grid3D.getResolutionZ()), while the calc grid declared in austal.txt omitted sk and therefore used the AUSTAL built-in default 0 3 6 10 16 25 40 65 100 150 200 300 400 500 600 700 800 1000 1200 1500 (3 m first cell). Ground-level road and parking emissions were released uniformly into the first 50 m of atmosphere instead of 0–3 m, suppressing near-source ground concentrations by roughly a factor of 7. The per-source sk is now written from the AUSTAL default explicitly.
    • Concentration GPKG spatial alignment in ConcentrationsQGISVectorLayerOutputModule.py. Three connected issues caused the QGIS-built GPKG of y00a output to disagree with the underlying AUSTAL grid: _data_cells was built from the .alaqs DB grid plus a hardcoded halo and ignored the y00a header; process() iterated y00a cells with delta = 250 in raw EPSG:3857 units while polygons were ~413 raw units wide, producing Point-in-polygon binning that summed multiple y00a cells into one polygon; and the contains() lookup was unnecessary. Fixed by reading xmin/ymin/delta/hghb from the y00a header, building _data_cells in absolute UTM, mapping y00a cells 1:1 to data_cells via direct array assignment, and reprojecting to EPSG:3857 only at the final endJob() step. Verified on a synthetic single-source test: 19 nonzero polygons, cell-by-cell match against the y00a DMNA.

    Documentation¶

    • Activity Profiles section in documents/USER_GUIDE.md rewritten. The previous description claimed profile values were [0, 1] activity multipliers and that zeroing a period deactivated the source. Both are wrong: profiles are non-negative shape factors, and the internal calendar-weighted normalisation redistributes mass to non-zero periods, leaving the annual total unchanged. The new section gives the multiplicative formula explicitly and points users at unit_year / ops_year for actual reductions.
    • BFFM2 limitations in documents/BFFM2_validation/BFFM2.md: the straight-line trajectory limitation applies only to standard ANP profiles. ADS-B course = CUSTOM profiles can describe arbitrary curved trajectories.
    • User Guide Create Output File section documents the ADS-B Data (Optional) widget and the ADS-B CSV column schema sourced from open_alaqs/core/tools/ads_b.py:validate_adsb_file.
    • CHANGELOG Compatibility subsection added to the 5.0.0 entry. Lists primary CI targets (QGIS 3.40.15 LTR and 3.44.9) and notes QGIS 4.x as experimentally supported.

    [5.0.0] - 2026-04-30¶

    First stable release after the rebuild. The 5.0 line is not backwards-compatible at the file-format level with the 4.x series — see the Migration section below for how to bring an old .alaqs study forward.

    Compatibility¶

    • QGIS 3.x (LTR / latest) — primary supported targets. The CI matrix runs the test suite against the QGIS Docker images qgis/qgis:3.40.15-noble (LTR) and qgis/qgis:3.44.9-noble (latest) for every PR.
    • QGIS 4.x (experimental) — the plugin has been used end-to-end on QGIS 4.x development builds throughout 2026 and is functional there. QGIS 4.x is not yet covered by automated CI; users running on 4.x builds are invited to report issues against this repository.

    Added¶

    • scripts/migrate_alaqs.py — CLI tool that rewrites a legacy 4.x-era .alaqs file in place against the current canonical schema. Supports two phases: (1) schema migration (add/drop tables and columns to match the reference template), (2) optional reference-data refresh (replace the contents of default_* tables with shipped CSVs). Handles the SpatiaLite metadata view and trigger dependencies that the legacy file format brings along, so files written with SpatiaLite 4.x or earlier migrate cleanly.

    • scripts/migrate_alaqs_gui.py — PyQt5 wrapper around the CLI for users who prefer a graphical interface. Exposes every CLI flag, surfaces the migration log live, and runs the migration in a worker thread so the UI stays responsive.

    • documents/AUSTAL/AUSTAL_OPERATION.md — operating guide for the in-plugin AUSTAL Dispersion Analysis dialog. Covers the executable selection, input-file strategy (existing files / from inventory / from CSV), grid configuration, execution, and result visualisation in step order.

    • CAEP/14 emission-index database validated against ICAO EEDB v31. The bundled default_aircraft_engine_ei table now matches the EEDB v31 anchors to 0% drift for every engine that appears in the AIRPORT_A test fixture (see tests/data/AIRPORT_A/AIRPORT_A_CAEP14_comparison.xlsx).

    • tests/data/AIRPORT_A/ new test fixture (Rotterdam-shaped airport with two engines: 01P20CM128 LEAP-1A26/26E1 and 11GE144 CF34-10E5A1), used to lock the bymode and BFFM2 emission paths against external references.

    • example/training/training_validation_reference.xlsx — paired-column reference spreadsheet validating the three plugin emission methods (bymode, BFFM2 trajectory, BFFM2 anchor) against equivalent CAEP/14 computations. Drift is documented per-pair (~0% bymode, ~2-3% BFFM2 NOx, <1% BFFM2 CO/HC).

    Changed¶

    • Emissions vector layer output now reprojects the receptor grid to EPSG:3857 in EmissionsQGISVectorLayerOutputModule.beginJob. The grid is built in local UTM (so user-supplied resolutions are honoured to ~2% on the ground), then reprojected so source/emission geometries — which are stored in EPSG:3857 throughout the rebuild — can be intersected in matching CRS. As a side effect, individual cell sums shift by ~1.5% relative to the pre-rebuild output because emissions redistribute across the projected cell footprints; aggregate totals are unchanged.

    • Movements CSV legacy compatibility — inventory_insert_movements now strips the trailing domestic column case-insensitively when it detects a 21-column header (the pre-rebuild export). Previously this silently dropped gate_emissions_code from column 13 onwards, which would inflate emissions because the default gate_emissions_code=1 re-enabled GSE on every movement. Affects users importing CSVs from pre-5.0 exports.

    • SQLSerializable._recreate_table → recreate_table (made public). Three call sites updated. Part of the schema-template registry work needed for tools/template_build/generate_templates.py to apply migrations consistently across all 24 SQLSerializable subclasses.

    • default_aircraft.engine_count is now TEXT (was INTEGER) to accommodate non-numeric engine-count markers (e.g. "C" for combined rotorcraft entries) that appear in some EEDB rows.

    • default_aircraft_engine_ei schema realignment — column count is 32 (one fewer than the 33-column 4.x baseline) after dropping the legacy pm10_prefoa3 field which was not used anywhere in the runtime. Column ordering was also realigned with the canonical template. Rows in legacy files are migrated transparently by --drop-extra-columns.

    • Dual-mode BFFM2 — the BFFM2 path accepts a bffm2_ff_source config field (trajectory default, or mode_anchor). Exposed in the Generate Emission Inventory dialog via a dropdown.

    • Create Output dialog "Advanced Options" group removed — the Method dropdown (with "ALAQS" as the sole choice), Towing Speed, and Vertical Limit fields have been removed. Method was never routed to any consumer, Towing Speed was written to a dict key no downstream code read, and Vertical Limit wrote to a DB column nothing queried — the actual LTO ceiling is EmissionCalculatorService.vertical_limit_m = 914.4 m (CAEP standard), hardcoded at the calculation boundary.

    Removed¶

    • 18 legacy 4.x-era tables are no longer part of the canonical schema and are dropped on migration with --drop-extra-tables. Listed for reference: default_aircraft_registrations, default_apu_ef, default_change_log, default_class_break, default_cost319_vehicle_fleet, default_dictionary, default_grid_definition, default_layer_definition, default_merge_definition, default_pollutants, default_table_updates, default_vehicle_co_ef, default_vehicle_hc_ef, default_vehicle_nox_ef, default_vehicle_pm10_ef, shapes_aircraft_tracks, user_stand_ef, user_taxiroute_aircraft_group. The COPERT5 vehicle EF data is now consolidated in the single default_vehicle_ef_copert5 table.

    • Legacy columns dropped on migration with --drop-extra-columns: geometry_columns.type, virts_geometry_columns.type (SpatiaLite 2.x metadata column), shapes_point_sources.type, shapes_parking.{park_time, vehicle_heavy, vehicle_light, vehicle_medium}, shapes_roadways.{vehicle_heavy, vehicle_light, vehicle_medium}, user_aircraft_movements.{aircraft_registration, domestic}, default_aircraft_engine_ei.pm10_prefoa3.

    Fixed¶

    • Migration of legacy SpatiaLite metadata (scripts/migrate_alaqs.py) — pre-fix, a --drop-extra-columns run on a 4.x-era file would abort with error in trigger ggi_<table>_geometry: no such table: main.geometry_columns because SpatiaLite ships dependent views (vector_layers, geom_cols_ref_sys) and triggers (ggi_*_geometry, geometry_columns_*_insert) whose bodies reference the metadata tables. The migrator now snapshots and recreates the dependent views and triggers around the column-drop step. Stale rows in geometry_columns referencing dropped tables are also cleaned up so QGIS does not see phantom layers when opening the migrated file. Regression test: tests/test_migrate_legacy_spatialite_metadata_regression.py.

    • Profile product normalisation — SourceWithTimeProfileModule.getRelativeActivityPerHour now divides by the calendar-weighted mean of (hour × weekday × month) over the inventory year. Profiles whose mean was not exactly 1.0 previously rescaled the annual emission silently away from EF × unit_year. Profiles authored to the OpenALAQS template convention (mean = 1.0) are unchanged byte-for-byte.

    • instudy='0' filter — sources marked excluded from the study via the instudy column are now filtered out at calculation time. The column had been declared in the schema for roadways, parking, gates, point sources, area sources, and runways but was never read by any module — the rows were silently included in totals.

    • Source.__init__ profile-name aliasing — Source rows now correctly read hourly_profile, daily_profile, and monthly_profile from the database. A key mismatch had caused the loader to fall back to the default profile silently for any source where the user had set a non-default value.

    • AmbientCondition NULL handling + METAR VRB winds — AmbientCondition.__init__ now uses explicit numeric defaults for every field instead of returning None on empty cells. The METAR-to-meteo converter writes 999 (AUSTAL calm-variable convention) for VRB winds instead of empty string. Together these prevent a TypeError: must be real number, not NoneType crash in AUSTALOutputModule on inventories with VRB METAR observations.

    • Parking cold-start at trip scale — the COPERT5 cold-start contribution is now applied once per parking trip rather than once per road segment when parking_include_cold_start=True. Default behaviour (cold start off) is unchanged.

    • Taxi Mach state-leak isolation — TaxiingEmissionCalculator.calculate_emissions now forces mach_number = 0.0 for taxi operations. The shared method["config"] dict was being mutated per flight segment by FlightEmissionCalculator, leaking the previous segment's terminal Mach (typically 0.15-0.40) into taxi BFFM2 lookups and producing 0.5-3% under-prediction on taxi fuel flow. The CAEP/14 BFFM2 formulation uses M=0 for ground operations.

    • Climbout installation correction — MovementSourceModule CAEP/14 installation correction for Climbout corrected from 1.012 to 1.013 (the 1.012 override disagreed with the bffm2.py docstring, comment, and default).

    • MES double-count fix — single-engine taxi main-engine-start emissions are now added exactly once per movement instead of once per taxi segment inside the MES window. Affects movements with gate_emissions_code=1 AND a non-null set_time_of_main_engine_start_after_block_off_in_s (or the before-takeoff variant) AND multi-segment taxi routes.

    • Gate emissions gating — MovementSourceModule now forwards the movement's gate_emissions_code to the gate emissions path, so code=0 movements no longer leak POLYGON-geometry entries.

    • Stop-and-go engine count — stop-and-go emissions now multiply by number_of_engines, matching the convention used for taxi and queuing time. Affects movements with number_of_stop_and_gos > 0; no effect on engine-only validation scope where stops are zeroed out.

    • CO/HC interpolation alignment with CAEP/14 — in the standard SL/HL-intersection case, EI now snaps to the horizontal mean value for any segment fuel flow above the APP anchor (SAE AIR-5715 slope-to-mean-value rule). The previous smoothed step disagreed with CAEP/14 by up to 8× EI at warm-humid AP-anchor conditions.

    • Log-noise suppression — OutputModule, TableViewWidgetOutputModule, and AUSTALOutputModule no longer log ERROR for zero-valued placeholder emissions synthesised for empty periods. Real missing-geometry bugs still surface.

    • AUSTAL diagnostic level + day-window correction — checkTimeIntervalinResults now logs at ERROR level (was DEBUG) when series.dmna and austal.txt files disagree. checkHoursinResults warning text and end_date assignment are now consistent at start + 23 h (AUSTAL convention: a day is 24 inclusive timestamps from 01:00..00:00).

    • Below-MSL airport elevation entry — spinBoxAirportElevation and spinBoxAirportTemperature now declare explicit minimum properties. Below-MSL airports (EHRD, EHAM, LLEY, etc.) and cold-climate annual means now round-trip correctly. Without the minimum, Qt clamped any negative value to 0 silently.

    • CSV receptor altitude optional — the receptor CSV loader now accepts a 3-column file (id, longitude, latitude) without silently producing an empty GeoDataFrame. Default receptor breathing height (1.5 m) is applied downstream by AUSTALOutputModule.getGridXYFromReferencePoint.

    Migration¶

    To bring a 4.x-era .alaqs file forward:

    python scripts/migrate_alaqs.py path/to/your.alaqs \
    --drop-extra-tables \
    --drop-extra-columns \
    --refresh-reference-data \
    --refresh-include-user-extensible

    --refresh-include-user-extensible overwrites default_aircraft, default_aircraft_engine_ei, and 5 other "user-extensible" tables with the shipped reference data; drop this flag if your study has bespoke entries you want to preserve. The migrator writes a .bak-<timestamp> backup before any change and rolls back on error, so the source file is safe.
