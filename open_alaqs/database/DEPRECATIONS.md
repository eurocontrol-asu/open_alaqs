# Database schema deprecations

This document tracks fields in `database/data/*.csv` that are retained for
compatibility but are unused at runtime. They are scheduled for removal in
a future schema-v2 migration.

## default_aircraft_engine_ei.csv — 12 of 32 columns deprecated

Columns dead at emissions-calculation runtime (populated by migration scripts,
never read by the calculation engine):

| Column | Reason | Kept for |
|---|---|---|
| `coolant` | Pass-through in Engine.py, never consumed | Round-trip to user exports |
| `combustion_technology` | Pass-through only | Round-trip to user exports |
| `technology_age` | Pass-through only | Round-trip to user exports |
| `eng_type` | Only read by `update_default_aircraft_engine_ei_csv.py` migration | Migration tooling |
| `bpr` (bypass ratio) | Only read by migration script | Migration tooling |
| `remark` | Only written by migration scripts | Manual annotation |
| `smoke_number` | Stored in default-dict, never read | ICAO EEDB contract |
| `smoke_number_maximum` | Stored, never read | ICAO EEDB contract |
| `status` | Zero runtime references | Unused |
| `engine_name_type` | Populated by migration, never read | Migration tooling |
| `fuel_type` | Overridden by computed logic (`engine_type` → AvGas / Jet Fuel) | User override (currently ignored) |
| `manufacturer` | Engine table pass-through; the aircraft-table version is what's actually used | Duplicate of aircraft-table field |

**Impact**: 12/32 columns unread. Removing them shrinks the CSV by ~30% and
eliminates per-row `setObject` overhead.

## Additional finding: `nvpm_ei` redundancy

`nvpm_ei` is the 13th underutilised column but sits in a different category —
not deprecated, just redundant.

- `nvpm_ei` and `pm10_nonvol` are numerically identical in EEDB (both are the
  non-volatile PM mass emission index, in g/kg).
- 3343 of 3384 rows in ANP_out.alaqs have non-null `nvpm_ei`.
- `nvpm_ei` is **not** in the schema dict (`EngineDatabases.py:235-263`), so
  `SQLSerializable.deserialize()` doesn't select it from the database.
- But production code reads the non-volatile PM mass EI via
  `ei_.getObject("nvpm_g_kg")`, and the key_mapping in `Engine.py:767`
  remaps `nvpm_g_kg` to the DB column `pm10_nonvol`. So the MEEM V1/V2 call
  path (Engine.py:283-294) gets the right value via `pm10_nonvol`.
- The only function that reads `nvpm_ei` directly (`meem_v1.load_from_engine_row`,
  via `row.get("nvpm_ei")`) is not called from production code.

**Conclusion**: no runtime impact today. The column is a CSV-export convenience
and an ICAO EEDB round-trip convenience. When schema v2 lands, the choice is
either drop `nvpm_ei` and keep `pm10_nonvol` as the single source of truth, or
drop `pm10_nonvol` and keep `nvpm_ei` (matches
ICAO EEDB 2021+ nomenclature). Current recommendation: drop `pm10_nonvol` and
keep `nvpm_ei` to align with ICAO EEDB, but this is a naming choice that
doesn't affect any calculation.

**Migration plan**:
1. schema-v1 (current): mark deprecated in `EngineDatabases.py`, document here.
2. schema-v2 (future release):
   - Drop columns from `EngineDatabases.py` schema dict:
     * `smoke_number`, `smoke_number_maximum`, `fuel_type`, `manufacturer`,
       `status`, `engine_name_type` (annotated DEPRECATED in current schema)
     * The other 6 deprecated columns are already absent from the schema dict;
       only the CSV / .alaqs file contents need cleanup.
   - Regenerate `default_aircraft_engine_ei.csv` without these 12 fields (20 cols remaining).
   - Resolve the `nvpm_ei` vs `pm10_nonvol` redundancy (see the nvpm_ei
     finding above). Recommended: keep `nvpm_ei`, drop `pm10_nonvol`, update
     `Engine.py:767` key_mapping from `"nvpm_g_kg": "pm10_nonvol"` to
     `"nvpm_g_kg": "nvpm_ei"`.
   - Add a one-shot `.alaqs` file migration that rewrites the
     `default_aircraft_engine_ei` table in-place when an old-schema file is
     opened. SQLite doesn't support `ALTER TABLE DROP COLUMN` before 3.35, so
     the migration must be `CREATE TABLE tmp; INSERT ... SELECT <new cols>;
     DROP old; RENAME tmp`.
   - Version-stamp the output files so downstream tools can detect schema.
     Proposed: write `PRAGMA user_version = 2` on migrated files.
   - Update the 6 test fixture `.alaqs` files similarly. Regenerate any
     reference outputs whose numeric values shift (none expected — the dropped
     columns are all runtime-dead).

**Schema v2 entry points** (for the future implementer):
- Touch points in Python: `EngineDatabases.py` (schema dict), `Engine.py`
  (key_mapping line 767 if nvpm rename is adopted, pass-through fields
  lines 784-787 for coolant/combustion_technology/technology_age cleanup).
- Touch points in data: `database/data/default_aircraft_engine_ei.csv`,
  all 6 `.alaqs` fixture files, possibly the `inventory_template.alaqs`
  generated by `generate_templates.py`.
- Touch points in docs: this file.

**Why defer**:
- No runtime impact from current state (verified). The 12 deprecated columns
  are either unread or read only by migration scripts; `nvpm_ei` data flows
  through `pm10_nonvol` via Engine.py key_mapping.
- Schema v2 is a breaking change for external tools that consume .alaqs
  files. Shipping it should be coordinated with a release that already
  introduces other breaking changes, to avoid forward-compat churn for no
  immediate benefit.

## database/src/ and database/scripts/ removed

The `database/src/` directory and the `database/scripts/` regeneration
pipeline have been removed: the CSVs in `database/data/` are now treated
as the frozen source of truth, populated externally and shipped with the
code. Users do not regenerate them.

The 6 files removed from `database/src/` (~35 MB total, zero references
anywhere in the codebase):

- `ICAO_EEDB.xlsx` — superseded by `edb-emissions-databank_v28c_web.xlsx`
- `N06_E02A_B19_out.alaqs` — orphan test fixture
- `caep_case_3_updated.alaqs` — orphan CAEP test case
- `inventory_template.alaqs` — orphan; `generate_templates.py` builds its own
- `old_blank_study.alaqs` — superseded by `new_blank_study.alaqs`
- `old_blank_study_mig.alaqs` — superseded migration artifact

The runtime-only file `default_aircraft.csv` survives in
`database/data/`; its older `database/src/` counterpart (902 rows,
semicolon-delimited) was the regeneration pipeline's intermediate
input and is no longer needed.

## Helicopter LTO infrastructure refactor (5.2.0 release)

The legacy helicopter emission-index table and its supporting class
hierarchy were removed in favour of live FOCA 2015 LTO computation
(`open_alaqs/core/tools/foca_heli.py`). The legacy pipeline carried
unverified per-mode emission indices and was never invoked by any
production code path.

**Removed entirely:**

| Artifact | Where |
|---|---|
| `default_helicopter_engine_ei.csv` (86 rows) | `database/data/` |
| Table `default_helicopter_engine_ei` | Schema (project template) |
| `class HelicopterEngineEmissionIndicesDatabase` | `core/interfaces/EngineDatabases.py` |
| `class HeliEngineStore` | `core/interfaces/EngineStore.py` |
| `class HelicopterEngineEmissionIndex` | `core/interfaces/Engine.py` |
| `Aircraft.getHeliEngineStore()` + initAircraft fallback | `core/interfaces/Aircraft.py` |
| `Movement._heli_engine_store` field + 4 call sites | `core/interfaces/Movement.py` |
| 61 helicopter rows from `default_aircraft.csv` | `database/data/` |
| 16 HELIPROF rows from `default_aircraft_profiles.csv` | `database/data/` |
| `Helicopter.DEFAULT_*_PROFILE_NAME`, `getDefault{Departure,Arrival}ProfileName()` | `core/interfaces/Helicopter.py` |

**Replaced by:**

- `default_helicopter.csv` (60 rows): helicopter catalog with `icao`,
  `variant_label`, `mtow_kg`, `engine_count`, `engine`, `max_shp_per_engine`,
  `is_default`.
- `default_helicopter_engines.csv` (86 rows): engine metadata with
  `engine_name`, `engine_full_name`, `engine_type`, `max_shp_per_engine`,
  `source`.
- `HelicopterStore`, `HelicopterDatabase`, `HelicopterEnginesDatabase`,
  `Helicopter`, `HelicopterEngine` in `core/interfaces/Helicopter.py`.
- Runtime per-category trajectory generation in
  `core/tools/foca_heli_trajectory.py` (replaces the 8-point HELIPROF
  profiles, which collapsed to a zero-length column at the runway
  threshold).

**Migration for users with existing .alaqs files**: pass
`--drop-extra-tables` to `migrate_alaqs.py` to drop the legacy
`default_helicopter_engine_ei` table from old files (their helicopter
movements will then resolve through the new `default_helicopter` /
`default_helicopter_engines` tables seeded by the migration).

## Added in 5.2.0: 5 MEEM v1 / nvPM columns in `default_aircraft_engine_ei`

The columns `press_ratio`, `meem_nvpm_m_i_f00_avg`, `meem_nvpm_n_i_f00_avg`,
`nvpm_m_max_mgkg`, `nvpm_n_max_nkg` were always read by
`EngineEmissionIndicesDatabase._load_meem_metadata()` but were missing from
the SQLSerializable schema declaration. Fresh templates therefore lacked
the columns and the MEEM v2 emission method silently degraded to bymode.

Now declared in the schema. Seed data in the shipped CSV is NULL for
these 5 columns (no MEEM data shipped); populate them with a separate
post-import script if needed. Without the columns populated, the MEEM v2
emission method continues to degrade gracefully to bymode (the soft
fallback in `_load_meem_metadata` is retained).
